# VideoPress

Веб-приложение для сжатия больших видеофайлов (включая 10+ ГБ) через `ffmpeg`.

![Превью страницы](./public/icons/preview.png)

## Что умеет

- Загружает большие файлы потоково (без хранения всего файла в RAM).
- Сжимает видео на сервере в фоновом процессе.
- Показывает статус обработки, прогресс и примерное оставшееся время.
- Поддерживает паузу, продолжение и отмену сжатия.
- Дает скачать готовый результат.
- Очищает папку результатов по клику на корзину.

## Как работает сжатие

1. Файл загружается в `uploads/`.
2. Сервер определяет длительность через `ffprobe`.
3. Запускается `ffmpeg` с выбранным профилем.
4. Результат сохраняется в `outputs/` в формате `.mp4`.

### Профили сжатия

- `high` — максимальное сжатие (меньше размер).
- `medium` — баланс качества и размера.
- `low` — лучшее качество (меньше сжатие).
- `web` — для сайта: видео вписывается в 1920×1080 (вертикальное — в 1080×1920) без увеличения, пики битрейта ограничены 6 Мбит/с, метаданные (в том числе GPS с телефона) удаляются. Рядом получаются постер (`.jpg`) и беззвучное превью на 4 секунды (вписано в 640×360) для наведения. Размеры и длительность готового видео приходят в статусе задачи (`media`).

Все профили выдают 8-битное видео (`yuv420p`): 10-битный H.264, который получается из HEVC с iPhone, браузеры не воспроизводят.

## Поддержка форматов

На вход можно подавать любые видео, которые читает `ffmpeg` (например, `.mp4`, `.mov`, `.mkv`).

На выходе:

- `.mp4` (H.264 + AAC)

## API

### Health

- `GET /api/health`
- Ответ: `{ "ok": true }`

### Загрузка и запуск

- `POST /api/upload`
- `multipart/form-data`:
  - `qualityPreset`: `high | medium | low | web`
  - `video`: файл
- Ответ: `{ "jobId": "..." }`

### Статус задачи

- `GET /api/jobs/:id`
- Возвращает статус, прогресс, размер исходника/результата и т.д.
- Для профиля `web`: `stage` (`compress` или `extras`, пока делаются постер и превью), `media` (`width`, `height`, `duration`, `hasAudio`) и `extras: ["poster", "preview"]`, когда всё готово.

### Скачать результат

- `GET /api/jobs/:id/download`
- Доступно только после завершения.
- Для профиля `web` ещё `GET /api/jobs/:id/download/poster` и `GET /api/jobs/:id/download/preview`.

### Пауза

- `POST /api/jobs/:id/pause`

### Продолжить

- `POST /api/jobs/:id/resume`

### Отмена

- `DELETE /api/jobs/:id`

Отмена удаляет файлы только этой задачи — результаты других пользователей остаются.

## Настройки

Переменные окружения (у всех есть значения по умолчанию):

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PORT` | `3000` | порт сервера |
| `DATA_DIR` | папка проекта | где лежат `uploads/` и `outputs/` |
| `MAX_UPLOAD_GB` | `5` | максимальный размер файла |
| `MAX_PARALLEL` | `1` | сколько видео сжимается одновременно, остальные ждут в очереди |
| `TTL_HOURS` | `24` | через сколько часов удаляются старые результаты |
| `MIN_FREE_GB` | `3` | сколько места на диске оставлять свободным |
| `WEB_X264_PRESET` | `medium` | скорость x264 для профиля `web`: `slow` даёт файлы меньше (для разового пережатия архива на мощной машине), `veryfast` — быстрее на слабом сервере |

Исходник удаляется сразу после сжатия, недогруженный файл — при обрыве загрузки.

## Развёртывание

Образ собирается в GitHub Actions при пуше в `main`: `ghcr.io/goldextremal/videopress:sha-<commit>` и `:latest`.

На сервере рядом с другим приложением за его Caddy:

1. `deploy/docker-compose.yml` → `/opt/videopress/docker-compose.yml`, рядом `.env` с `CADDY_NETWORK` (Docker-сеть Caddy) и `IMAGE_TAG`.
2. `docker compose up -d` — контейнер ограничен 1 ядром и 1 ГБ памяти.
3. `deploy/press.caddy.example` → папка дополнительных сайтов Caddy, с логином и хэшем пароля (`caddy hash-password`). Пароль в репозиторий не попадает.

## Важные замечания

- Сжатие выполняется локально на сервере, а не в браузере.
- Для очень больших файлов убедитесь, что на диске достаточно места (`uploads` + `outputs`).
- Память не перегружается за счет потоковой загрузки, но диск и CPU используются активно.
